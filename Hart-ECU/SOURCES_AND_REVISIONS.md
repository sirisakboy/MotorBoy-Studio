## Review notes and exclusions

- `python-can` is a general host CAN library with multiple hardware-specific backends. Only its runtime package and key project/license metadata were extracted; tests/docs/examples are not extracted. Some hardware backends require optional packages, proprietary vendor drivers, or compatible OS support. The companion sidecar is not evidence that any physical adapter works.
- `btleplug` provides BLE GATT, not Bluetooth Classic/SPP, and does not know adapter-specific service/characteristic UUIDs. Its crate source is retained for review but is uncompiled in this environment. The local `adapters/btleplug_scan/` wrapper only lists host adapters and scans advertisements; it does not connect or access GATT characteristics and is itself uncompiled.
- `ble-serial` is an optional BLE-UART-to-PTY/TCP bridge. Its upstream Windows setup can require disabling Secure Boot for a virtual COM driver; this bundle explicitly does not recommend disabling Secure Boot. Its CLI defaults to read/write, so it is not approved for live ECU access without mode/UUID/security review.
- The KDS/SDS derivative keeps only `KDS PID`, `Supported PIDs Z1000`, `Supported PIDs Z750`, and `Service Codes`. It excludes `AT-Commands`, `SID`, `Raterei`, `Test`, Bluetooth configuration/reset commands, clear/reset functions, standards PDFs, code, binaries and generated repository content. The workbook values remain unverified.
- The Honda CRF250L data is a community diagnostic sample with unknown fields and unresolved exact year/software/ECU identity. It is not an XDF or universal Honda profile.
- The `CRF110F 2019 / 38770-KYK-D12` Honda XDF is an unmodified GPL-3.0 research candidate; its declared `REGION size="0x65536"` conflicts with the README 64 kb, and offset semantics remain unresolved. See `vehicle_profiles/engine/honda/CRF110F_2019_KYK-D12_candidate/SOURCE_NOTE_TH.md`.
- MotoXDF Wiki page-level CC BY-SA does not clear possible upstream restrictions. The Ducati 5AM M620 XDF author/source chain links to GuzziDiag/Pauldaytona definitions and a public CC BY-NC adaptation statement; no Ducati XDF was copied. Other Honda XDFs with immobilizer/opaque flags/testing or model-ID ambiguity were also excluded. See `XDF_CANDIDATE_AUDIT_TH.md`.
- `DanCycles/HayabusaGen3` was audited but not redistributed: its MIT-repository XDF includes `modifypassword`/`openpassword` fields plus ten `XDFPATCH` blocks, several of which disable controls. We removed the local copy instead of carrying password metadata or stripping it to bypass author protection; see `XDF_CANDIDATE_AUDIT_TH.md`.
- No WiCAN firmware was copied because no usable adapter protocol endpoint/framing was established; the IP socket module is strictly generic and does not claim WiCAN compatibility.
- No stock BIN/ROM files are included. No auto-checksum is approved. ABS, separate TCU, cluster, BMS/controller and verified immobilizer definitions remain gaps; see `vehicle_profiles/PROFILE_COVERAGE.csv`.
- `SimpleBLE` (BUSL-1.1), `OBD2_KLine_Library` (GPL-3.0 generic MCU project), mixed-license definition repositories, and unlicensed/hardware-specific candidates remain research-only. No whole repository was imported.

License obligations travel with each component; review compatibility before combining, modifying or distributing the pack or an application based on it.
